# 안전 동작

## Fake 조립

- Robot Node를 기동해 Action을 실행하는 Launch 경로는 `mode:=fake`입니다. `fake_motion_clear`은 시뮬레이션용 이동 허가입니다. 작업자 완료 신호 후 3초가 지나도 최신 이동 허가를 별도로 확인합니다.
- Robot Node는 공통 Action 실행 슬롯을 사용합니다. Fake Action 실행 중에도 별도 실행 스레드에서 STOP과 Watchdog을 처리할 수 있습니다. Robot은 상태 시각과 관제 인스턴스 ID를 확인합니다. 동작 중 관제 상태 유실 또는 인스턴스 변경 시 정지를 래치합니다.
- GUI는 관제와 Robot에 독립적으로 STOP을 요청합니다. 서비스 성공은 래치 접수입니다. Fake Robot이 Action을 끝내고 유휴 상태를 보고하면 정지 확인으로 표시합니다. 최초 정지 원인은 래치와 TaskResult, JSONL 및 이벤트에 연결하고 추가 오류는 별도 기록합니다.
- Goal 수락·종료가 불명확하면 STOPPED를 유지하고, 종결 결과가 확인될 때까지 RESUME을 허용하지 않습니다. STOP 재요청은 같은 ID로 제한된 횟수만 시도합니다. RESUME 응답 또는 후속 상태가 불명확하면 다시 정지 요청을 보내고 관리자 조작을 기다립니다.
- READY에는 최신 이동 허가, 알려진 현재 자세, 유휴 상태, 확인된 그리퍼 상태와 빈 파지, 비활성 힘·순응 제어가 필요합니다. 안전 상태가 불확실하면 RECOVER에서 CHECK를 거절합니다. 복구 시 작업자가 현장을 확인한 후 GUI 또는 CLI에서 RESUME을 사용합니다. 중지된 작업은 새 CHECK로 다시 시작합니다.
- 실물 어댑터는 `RobotAPI.request_stop()`을 두산 ROS 서비스 `motion/move_stop` (`dsr_msgs2/srv/MoveStop`, 로봇 네임스페이스 적용)에 연결할 수 있습니다. 어댑터의 STOP 전송이 블로킹 동작이나 로봇 상태 잠금과 경합하지 않도록 구성해야 합니다. 컨트롤러 및 힘·순응 제어 피드백으로 실제 정지를 확인하고, 설치별 정지 타입과 우선순위를 검증합니다.
- 소프트웨어 Watchdog, GUI·CLI·음성 STOP은 안전 등급이 인증된 비상정지 기능을 대체할 수 없습니다. 실물 도입 전 독립 비상정지 회로, 작업 공간 접근 감지, 툴·좌표 교정, 통신 중단 대응과 힘·토크 한계를 검증해야 합니다.


## L/R 외부 검사

- `mode:=inspection`은 Robot Node를 기동하거나 Robot Action을 호출하지 않습니다. 외부 서비스로 존재 및 체결 상태를 조회하며, 체결 조회 서비스에서 힘·순응제어나 마무리 조임을 시작하면 안 됩니다.
- `WORKER DONE`은 준비 완료 통보입니다. `READY`는 새 결과 수집을 받을 수 있는 상태입니다. 실제 장비 조작은 현장 검증 절차와 독립 안전 조건에 따릅니다.
- `inspection_stop_latched`는 관제 결과 수집이 정지되었음을 뜻합니다. 실제 장비 정지는 독립 보호 회로와 검증된 Robot 정지 경로에서 확인합니다. GUI·CLI의 RESUME은 결과 수집 래치를 해제합니다. [L/R 통신 계약](INTERFACES.md#lr-최소-통합-계약)
